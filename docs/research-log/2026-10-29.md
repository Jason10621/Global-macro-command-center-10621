## 오늘 구현한 것
: **경제 AI 도우미(Gemini)** — 화면 오른쪽 아래 "✦ 경제 AI에게 질문" 버튼 → 채팅 패널. 지금 보고 있는 국가의 실제 데이터(종합 점수·카테고리 점수·지표 최근값과 리스크 판정·IMF 전망)를 시스템 프롬프트로 함께 보내 숫자를 지어내지 않고 화면 데이터에 근거해 답하게 함. 투자 조언 금지, 학습용 규칙이라는 점 명시, 추천 질문 버튼, 새 대화, 오류 안내 포함. 호출 경로는 이중: ① Vercel이면 `/api/chat` 서버 함수(키는 서버 환경변수) ② 서버가 없는 GitHub Pages면 방문자가 입력한 본인 키를 브라우저(localStorage)에만 저장해 Gemini 직접 호출.

: **종합 리스크 스코어 가중치 v2** — 동일 가중 평균 → 3단계 가중 평균(핵심 지표 ×1.5: 성장·물가·실업·정부부채·재정수지·경상수지·외환보유액 / 일반 ×1.0: 청년실업·민간신용 / 참고 ×0.6: 시가총액·대출금리·M2). 카드에 "핵심" 배지와 가중 평균 문구 반영. 가중치는 `WEIGHTS` 한 곳에서 수정.

: **이벤트 타임라인 조정** — 전 세계 사건 5→8건(2001 IT버블·9·11, 2018 미·중 무역분쟁(국가별→전 세계로 승격), 2023 은행권 불안 추가), 국가별 사건 추가(한국 2003 카드채 사태, 미국 2011 신용등급 강등, 일본 2011 대지진, 인도 2016 고액권 폐지, 인도네시아 2013 긴축 발작, 멕시코 2009).

: **FRED 활성화 준비** — `.env.example`·README에 키 발급 → Actions 시크릿 등록 → 재배포 순서 정리. (키 자체는 개인 자격증명이라 직접 등록하지 못함 — 아래 "막힌 문제" 참고)

## 오늘 막힌 문제
: 1) GitHub Pages는 서버가 없어 Gemini 키를 숨길 곳이 없음 — 정적 코드에 넣으면 누구나 볼 수 있어 도용됨.
: 2) 가중치·이벤트를 "피드백 기반"으로 조정하려 했으나 아직 실제 사용자 피드백을 수집하지 못함.
: 3) FRED 키는 본인이 발급해 GitHub 저장소 시크릿에 직접 넣어야 해서 오늘 활성화까지는 못 함.

## 해결 과정
: 1) IMF·FRED와 같은 "이중 경로"로 설계: 서버가 있으면 프록시(`api/chat.js`, 길이 제한·입력 검증), 없으면 사용자 본인 키를 입력받아 브라우저에만 저장. 프록시가 404/503이면 한 번만 확인하고 사용자 키 경로로 전환.
: 2) 피드백이 없으므로 "위기와 직결되는 지표 vs 국가 구조에 따라 달라지는 지표"라는 논리로 가설 가중치를 세우고, 코드·화면·DEVLOG에 "검증 전 가설"이라고 명시. 한 곳만 고치면 되게 설계. 결과적으로 한국은 84점 그대로(큰 변화 없음) — 효과는 지표 편차가 큰 나라에서 더 클 것으로 예상(미검증).
: 3) 설정 순서를 README에 정리. 시크릿 등록 후 Actions에서 Run workflow만 하면 됨.
: 검증: `npm run build` 통과 → `vite preview`(서버 함수 없는 환경)에서 키가 없을 때 입력 안내가 뜨는 것 확인, 가짜 키 + fetch 모의로 요청 주소·키 헤더·시스템 프롬프트에 한국 데이터가 실리는 것까지 확인한 뒤 가짜 키 삭제. **실제 Gemini 응답 품질과 Vercel `/api/chat` 실배포는 아직 미검증.**
